# LRN-0001 — Staged publishing 0.0.0-stage no npm atrasa disponibilidade do tarball .tgz de pacotes novos

## Context

**Ticket:** TCK-0005
**PRR:** PRR-0006
**Category:** telemetry-insight
**Severity:** low

## Signal That Originated This Learning

Na publicação inaugural de `@aredes.me/mcp-tse@0.1.0`, o npm registrou inicialmente o placeholder `0.0.0-stage` (`16:53:49Z`), promoveu o packument `latest: 0.1.0` (`16:57:57Z`) e só tornou o tarball `mcp-tse-0.1.0.tgz` disponível com `HTTP/2 200` alguns minutos depois (`17:02:40Z`), causando `E404` temporário em `npm pack` / `HEAD`.

## Cause / Pattern

Para pacotes novos em escopo `@aredes.me/*`, o *staged publishing* do npm expõe o JSON de metadados (`dist-tags` / `versions`) ligeiramente antes da replicação final do arquivo `.tgz` na CDN.

## Impact

Checagens apressadas de P10 ou `npx -y` disparadas nos primeiros minutos após `npm publish` podem falhar por `404` transitório no tarball mesmo com `npm publish` exit `0`.

## Recommendation

Verificar HTTP 200 no dist.tarball alem do packument antes de executar npx smoke ou revisao P10
